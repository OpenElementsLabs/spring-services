# Behaviors: Comment author as `@ManyToOne UserEntity` association

## Entity mapping

### Author is mapped as a lazy ManyToOne to UserEntity

- **Given** a fresh database schema generated by Hibernate from `CommentEntity`
- **When** the schema for the `comments` table is inspected
- **Then** there is a column named `author_id` of type `UUID`, declared `NOT NULL`
- **And** there is a foreign key constraint named `fk_comments_author` from `comments.author_id` to `users.id`
- **And** there is no column named `author` on the `comments` table

### Author association is lazily loaded

- **Given** a persisted `CommentEntity` with an associated `UserEntity` author
- **When** the comment is loaded via `commentRepository.findById(...)` and the resulting entity is inspected without calling `getAuthor()`
- **Then** the author proxy is not yet initialized (no SQL query is issued for the `users` table)

### Author is fetched on demand

- **Given** a persisted `CommentEntity` with an associated `UserEntity` author
- **When** `getAuthor()` is called on the loaded entity inside an active transaction
- **Then** the author is loaded and the returned `UserEntity` exposes the correct fields (`id`, `name`, `email`, `avatarUrl`)

## Comment creation

### A new comment is associated with the current user

- **Given** an authenticated request from a known user
- **When** `commentService.create(new CommentCreateDto("hello"))` is invoked
- **Then** a new `CommentEntity` is persisted with `author_id` equal to the current user's `UserEntity.id`
- **And** the returned `CommentDto.author()` matches the current user's `UserDto`

### A new comment is associated with a freshly provisioned user on first login

- **Given** an authenticated request from a JWT subject not yet present in the local `users` mirror
- **When** `commentService.create(new CommentCreateDto("hello"))` is invoked
- **Then** the user is lazily provisioned in the `users` table
- **And** the new comment's `author_id` references the freshly provisioned user
- **And** the foreign key constraint is satisfied

### Comment creation rejects unauthenticated requests

- **Given** no authenticated subject is bound to the current request
- **When** `commentService.create(new CommentCreateDto("hello"))` is invoked
- **Then** the call fails (no comment is persisted, no user is provisioned)

## Comment retrieval

### Comment retrieval returns the author DTO without an extra service lookup

- **Given** a persisted `CommentEntity` whose author is a known `UserEntity`
- **When** `commentService.findById(commentId)` is invoked
- **Then** the returned `CommentDto.author()` equals `UserDto.fromEntity(authorEntity)`
- **And** no call is made to `userService.findById(...)`

### Listing many comments uses a batched author fetch

- **Given** 100 persisted comments authored by 5 distinct users
- **When** `commentService.getAll()` is invoked and each returned `CommentDto.author()` is read
- **Then** the total number of SQL queries against the `users` table is at most `ceil(100 / 50) = 2`
- **And** every returned `CommentDto` exposes the correct author

### Comment DTO shape is unchanged

- **Given** a persisted `CommentEntity`
- **When** `commentService.findById(commentId)` is invoked
- **Then** the returned `CommentDto` has the fields `id`, `text`, `author` (as `UserDto`), `createdAt`, `updatedAt`
- **And** the field types and order are identical to the pre-refactor DTO

## Referential integrity

### Inserting a comment with a non-existent author UUID fails

- **Given** an attempt to persist a `CommentEntity` whose `author` references a `UserEntity` not present in the database
- **When** the entity is flushed
- **Then** the database raises a foreign key violation
- **And** the violation surfaces as a `DataIntegrityViolationException` (or subclass) at the Spring Data layer

### Deleting a user that still has comments is rejected

- **Given** a `UserEntity` that is referenced as the author of at least one persisted `CommentEntity`
- **When** an attempt is made to delete that `UserEntity`
- **Then** the delete is rejected by the foreign key constraint
- **And** the comment row remains intact

### Deleting a user with no comments succeeds

- **Given** a `UserEntity` that is not referenced by any `CommentEntity`
- **When** the `UserEntity` is deleted
- **Then** the delete succeeds and no constraint is violated

## UserService API exposure

### `getCurrentUserEntity()` is publicly callable and returns the managed entity

- **Given** an authenticated request from a known user
- **When** `userService.getCurrentUserEntity()` is called
- **Then** it returns the managed `UserEntity` for the current JWT subject
- **And** the entity is attached to the current persistence context

### `getCurrentUserEntity()` provisions a new user on first call

- **Given** an authenticated request from a JWT subject not yet in the local `users` mirror
- **When** `userService.getCurrentUserEntity()` is called
- **Then** a new `UserEntity` is persisted with the JWT's `sub`, `name`, `email`, and `avatarUrl`
- **And** the returned entity has a generated `id`

### `getCurrentUserEntity()` updates drifted JWT claims

- **Given** an existing `UserEntity` whose `name` differs from the current JWT's `name` claim
- **When** `userService.getCurrentUserEntity()` is called
- **Then** the entity's `name` is updated to match the JWT claim
- **And** the change is persisted

## Audit log integration

### Comment create still emits an audit event

- **Given** an authenticated request from a known user
- **When** a comment is created via `commentService.create(...)`
- **Then** exactly one `INSERT` audit log entry is recorded for the `CommentEntity` type with the new comment's id

### Comment update still emits an audit event

- **Given** a persisted comment authored by the current user
- **When** the comment is updated via `commentService.update(...)`
- **Then** exactly one `UPDATE` audit log entry is recorded for that comment id

### Comment delete still emits an audit event

- **Given** a persisted comment
- **When** the comment is deleted via `commentService.delete(...)`
- **Then** exactly one `DELETE` audit log entry is recorded for that comment id
